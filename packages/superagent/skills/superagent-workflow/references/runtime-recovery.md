# 运行等待与上下文恢复（DeepSeek Harness）

在派发耗时操作、上下文持续增长，或等待来源不明时读取。用户暂停指令始终优先，后台完成结果或恢复建议不能覆盖用户暂停。

进程内引擎模式的持久任务通过 [概览与证据](engine-evidence.md) 中的 `engine_overview`、`engine_evidence` 与 `engine_control` 核对恢复，不另派重复子代理。下文原生等待与上下文恢复规则适用于当前主会话及原生 `subagent` 协作。

## 等待前约定复查与真实进展判定

- 派发长操作或子代理前明确可观察的有效进展与复查条件；原生 `subagent` 已发出且仅剩等待结果时，直接结束本回合交由宿主在子代理结算时自动唤醒，或使用原生 `wait_agent`，不编写轮询 sleep 循环。
- 区分等待来源：**模型推理中**（宿主请求已发出）、**工具/命令运行中**（真实进程或任务 ID 未结束）、**等待用户操作/授权**、**等待子代理完成**、**待主线验收** 与 **状态未知**（证据不足，先做低成本区分检查）。重复查询状态本身不算新进展。
- 改派同一写入范围前，必须确认原执行者及相关子代理已停止写入；发出 `interrupt_agent` 或任务 `pause/cancel` 请求仅代表中断已受理，不等同于外部副作用已全部停止。

## 提前减少上下文负担与交接恢复

- 大体积命令输出、测试日志与媒体原件落盘保存，回包仅保留摘要、关键行列与文件路径引用；未变化的画面或产物复用同版本既有检查。
- 会话上下文增长时，优先使用宿主实际暴露的 `/compact` 压缩能力，或用 [development-handoff](../../development-handoff/SKILL.md) 整理结构化交接块（目标、当前状态、已定裁决、关键文件、验证结果、约束与下一步动作），在新会话或精简子代理中按交接块核对真实文件状态后继续推进，不把摘要本身谎称为宿主底层历史已压缩。
