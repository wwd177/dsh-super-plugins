# 协作与独立评审（DeepSeek Harness）

本次需要分工，或用户要求诊断协作收益时读取。持久多成员任务统一使用 SQLite WAL 持久编排引擎（见 [团队筹备与右侧工作台](execution-engine.md)）；下文原生 `subagent` 规则用于单轮轻量勘查或独立交叉评审。主线持有最终整合责任，简单或紧耦合任务直接处理，不因工具可用就拆分。

## 模型与推理强度

主代理沿用用户手动选择的模型与推理强度。子代理按任务难度与当前会话允许列表配置，详见 [Harness 原生接线](deepseek-harness.md)：

- **局部低复杂度任务（`low`）**：提取、格式整理、单一明确检查，在允许列表包含 `flash/lite/mini` 轻量模型时优先采用，并使用较低推理强度。
- **常规跨文件实现（`medium`）**：选能处理相应上下文与依赖的主力模型及中等强度。
- **复杂根因、强依赖或高风险评审（`high`）**：采用强推理模型与高推理强度；若目标模型不支持显式 `reasoningEffort` 参数则沿用该模型默认配置，不修改全局设置或凭据。

用户明确限制费用或调用量时，核对宿主是否实际执行上限，并计入子任务与在途调用；仅在宿主会话事件提供真实 token 统计时报告 `usage`，缺失记未知，严禁由字符或字节数推算 Token。

## 轻量原生 `subagent` 派发规范

使用 DeepSeek Harness 原生 `subagent` 工具派发单轮独立勘查或评审时，默认不继承母会话历史，必须在 `prompt` 中完整交代最小任务包：

```json
{
  "description": "核对导出报告重复标题",
  "prompt": "只读检查 build/report.html 是否存在重复二级标题，保留 archive/ 目录不改。返回重复项及行号，或确认无重复。"
}
```

仅当短消息与文件引用无法传达必需上下文时，才使用 `subagent_fork`。每位协作者应负责「调查 → 修改 → 验证」的完整闭环，在任务包中明确：
- 用户目标、负责产出的具体结果及允许的副作用；
- 输入的具体版本、文件路径与真实约束（包含本轮最新用户授权与纠正）；
- 负责的 `writeScopes`（共享工作目录内同一文件保持唯一写入者，保留他人改动）；
- 验收标准、可执行行为验证命令与回传摘要格式。

需要等待原生子代理结果且当前无其他独立工作时，结束当前回合由宿主在子代理完成时自动唤醒，或按需调用 `wait_agent`，不编写空转轮询脚本。

## 持久引擎交回、行为门禁与返工验收

多成员依赖协作统一保存在 `engine.sqlite` 持久引擎（见 [概览与证据](engine-evidence.md) 与 [注册检查与验收](engine-acceptance.md)）：
- 宿主执行完成、客观 `checks` 验证与调用方 `accept` 三者分开审查；无 `checks` 的任务保持 `not_verified`。
- **行为门禁**：开启 `autoAccept: true` 必须包含至少一条 `node_test` 可执行行为测试，严禁用 `file_exists` / `file_contains` 静态检查冒充行为完成。
- **写入隔离**：引擎调度器对重叠 `writeScopes` 自动施加运行时互斥锁（`write-scope-lock`），并在任务结束后拦截声明范围外的新增工作区文件（`write_scope_guard`）。
- 验收不通过时优先用 `engine_control({taskId, action:"rework", reason:"具体修改意见", expectedRevision})` 打回返工，引擎会自动注入上轮失败检查明细。
- 多成员产物需合入项目主目录时，由唯一整合负责人按 [最终集成](integration.md) 合并并运行项目级终检。

## 独立验收

关键交付或高错误代价修改，优先交由未参与编写的独立子代理对照原始用户需求、边界条件与负向用例做实跑核验；自审须如实标明自审局限，文字评语不能替代真实命令或界面验证证据。
