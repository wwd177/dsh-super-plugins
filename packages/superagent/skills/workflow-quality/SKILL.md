# 工作流质量与收口

目标是把授权范围内的工作完整做完，并提供与结论匹配的证据。检查数量、文件数量和日志长度不是交付质量。

## 开始时确定完成条件

从当前请求、既定约束和实际文件中整理：最终交付是什么、必须保留什么、哪些结果可观察、分别用什么验证。已有足够信息就继续，不重新采访用户。将关键假设写明，只有会改变正确性且无法查证的缺口才询问。

复杂或跨轮任务沿用本任务的一份当前状态记录，保存入口、完成条件、当前版本、已发现缺陷和未验项。可直接用项目现有记录；不要强制三份计划文件、固定阶段数或每两次操作写一次日志。不同任务不共用“最新文件”指针。

## 找到产生问题的源头

先重现最小失败，沿“原始输入 → 实际生效的skill/模板 → 编译或生成 → 最终正文/产物 → 下游”定位第一次发生偏差的位置。只改最终副本或追加正确说明，不能证明上游再执行不会重新产生错误。

确定性缺陷先留失败输入与预期，再修产生错误的代码、规则或绑定，并从原输入重新运行。若本次只修静态成稿、没有再生成入口，明确修复范围；不为凑“根治”修改无关skill。反复修正同类问题时先检查权威来源是否分裂、旧缓存/旧模板是否仍在生效，而不是继续追加同义禁令。

## 一次完成受影响链路

列出实际生产者与消费者，只运行本次涉及的角色；用户明确要求完整链路时覆盖完整链路。各阶段独立决定其职责，不能仅复制同一个状态包就声称这些skill已经独立执行。

修改后同步所有当前生效的模板、正文、摘要与引用；历史快照保留为历史。逐项看最终可复制正文，不只看JSON字段、文件存在或哈希。跨阶段状态、时间点与约束的作用范围分别检查。

媒体提示词中，首帧只约束所选瞬间，后续收握、释放、生成/消散按既定过程推进；换轴改变投影，不重置世界状态和解剖手；中途续接使用当前相位及剩余事件，不重用单元原首帧、重播完成动作或恢复旧持有者。已确认的高速、急停、瞬移和群战强度继续保留。

## 用能证伪的验证

分开记录三类证据：

- **机械验证**：语法、链接、时长算术、版本/哈希、合成事件重放。只能证明这些显式条件。
- **行为验证**：让实际生产者从原始请求生成真实文本/软件输出，按预先确定的结果条件审查；同时保留旧版本或无改动对照。人工自审注明自审，不能冒称独立执行。
  - 在多代理执行引擎（`v0.17.x`）中严格区分信任层级：`node_test`（引擎冻结在不可变上下文库中的测试脚本）可用于 `autoAccept: true`；`command_test`（多语言项目内测试命令，如 `pytest`/`cargo test`/`go test`/`dotnet test`）只能到达 `checked` 并须显式 `accept` 复核，以防被测仓库内的测试脚手架被同次改动弱化或绕过。
  - 核对写入边界时，必须以任务起点提交或基线做完整双树 diff（含新增、删除、重命名、符号链接与目录联结），不得仅凭工作区 `git status` 或“核心文件存在”宣告未越界。
- **实际媒体/现场验收**：只在获得相应素材并实际查看、播放或操作后成立；规划和文本回归不能升级为实片通过。用户禁止生成时保持媒体未验，完成其授权的文本工作。

重要行为尽量加入未用于修规则的保留案例，结果条件描述意思和行为，不要求全文与参考答案一致。只有运行和授权均支持时才进行独立评审；本技能不自行授权分派、调用外部模型或生成媒体。不能独立执行时保留局限，不用确定性格式化器冒充模型。

## 复用回归并及时收口

维护一份固定案例目录和一个入口，新增的是复现新失败的案例，不是每轮复制全部夹具和脚本。区分独立原始案例、变体、检查断言、阶段视图、重复运行；它们不能相加为“模型成功次数”。不要从这些计数推断成功率或一步到位提升。

已有合法当前来源记录时读取它，不按日期或修改时间猜“最新”。版本不符则明确指出，修订当前来源后再运行；不自动改预期或重新签名来让测试通过。跨skill案例按[固定回归方法](references/cross-skill-regression.md)执行。

相关验证通过且未再修改相关输入时，停止重复检查并交付。只在新变更、失败或新证据出现后补跑受影响项。开放缺陷直接修；缺乏授权或真实素材的验证单独列出，不能偷偷缩小用户要求来宣告完成，也不因这些外部缺口重复做已通过的文本检查。

最终说明：改了什么、解决哪种原因、实际验证与局限、仍需处理的事项。不要把“还有没有遗漏”留给用户充当默认测试计划。来源与明确未采用的上游做法见[研究与取舍](references/sources.md)。
